# IceCream private receive acknowledgement regression

Run `./scripts/icecream_private_receive_ack_tests/run.sh` after the pinned IceCream 2.0.4 patch has been applied to Pods. The macOS runner constructs actual CloudKit SDK operation and record objects, but never constructs a CloudKit container or submits to a server. It checks page-2 apply failure and a healthy repeated pull, both checkpoint writes and their order, partial and incomplete results, expired-zone cursor recovery, competing pulls, reset and shutdown, and cold-start zone creation recovery.

The optional standalone simulator process uses the real SyncObject and in-memory Realm. See run.sh for arguments; use an already booted disposable simulator, not a normal app or real device. This separately checks rollback of an injected transaction error, no outbound echo, exact record identity, and atomic replacement of a synthetic asset. It disables the Realm SDK update checker in the process before opening Realm. It does not simulate physical disk-full or real opaque server cursors (the offline checkpoints use nil cursors and verify zero writes on failure), and does not assert transactional atomicity between asset files and Realm, server conflict merging, or recovery of previously skipped history.

The simulator check also captures the outgoing record from a real Realm List<String> write, clears its last value, and verifies the SDK marks the cleared field as changed. It models the changed-keys merge and passes the resulting record through receiving IceCream to verify the old list disappears while an unrelated list is preserved. The merge simulation does not contact CloudKit.
